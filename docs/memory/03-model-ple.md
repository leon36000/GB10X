# Model contract and PLE hash

Reviewed: 2026-09-07. Code: `gb10x-core/src/{qwen38,ple_hash}.rs`.

- Model: `Qwen/Qwen3.8-Flash-Next`; pinned revision
  `34567a4712bc9766c4449e2e98e4468bfa24d915`; architecture family `qwen4_exp`.
- The reduced config fixture is an exact field/type projection of the official pinned config,
  not the complete original file. Activation, attention bias, dtype, RoPE type and nested rotary
  factor are now required, typed and pinned; 15 mutation/omission/type cases are rejected.
- PLE: 2-/3-gram, 8 heads per order, 16 total; EOS `248044`. Hash has a two-token history and
  speculative begin/abort/full-commit/accepted-prefix operations.
- Correct arithmetic: products/XOR retain low 64 bits, reinterpret as signed i64, then positive
  Euclidean remainder. Unsigned remainder was demonstrably wrong on accepted overflow inputs.
- Reference Transformers revision: `f62dc9bf2c90353b442a56e74391fbb8c689b55e`.
  Three upstream files are SHA-256 pinned before executing unmodified hash methods on CPU.
- `scripts/generate_ple_reference.py` substitutes only the large embedding lookup with a row-ID
  recorder. Fixture: 46 positions × 16 heads = 736 expected IDs. Six public-API tests cover EOS,
  signed overflow, large u32 tokens, restored context and speculative abort/partial commit.
- Seed `1234` and multipliers `[23703573157769,20109073645365,8052911324071]` are generated by the
  pinned upstream constructor. `verify_qwen38_ple_hash_buffers` / `gb10x-plepack hash-verify`
  now resolves the three exact persistent state-dict names, requires I64 `[3]`, `[16]`, `[16]`,
  and compares their 280 little-endian payload bytes with those defaults using bounded file reads.
  The fixture proves its parser and comparison behavior, not agreement with a released checkpoint.
- Ordinary released-vocabulary cases already matched before the fix. Do not claim an observed
  full-model inference failure from synthetic overflow cases.
