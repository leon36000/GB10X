# GB10X Native M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the first real GB10-native execution layer: strict CUDA `sm_121a` build/probe gates, an executable CUDA smoke path, exact safetensors-backed PLE row access, and the first correctness-gated CUDA kernel without making any unverified performance claim.

**Architecture:** Host-independent Rust logic remains testable on ordinary CI. Native CUDA exists only behind the `native-cuda` feature in a dedicated `gb10x-cuda` crate; there is no CPU fallback pretending to be CUDA. The C ABI hides CUDA/C++ ABI details from Rust, while every native artifact is compiled specifically for `sm_121a`. Native compile evidence and real-GB10 execution evidence are recorded separately.

**Tech Stack:** Rust 1.98+/edition 2024, CUDA C++/CUDA Runtime API, `nvcc`, `sm_121a`, BF16, safetensors format parsing, mmap, SHA-256, GitHub Actions host gates, DGX Spark native evidence commands.

**Spec:** `docs/superpowers/specs/2026-08-31-gb10x-cache-first-v3-design.md`

## Global Constraints

- Production target is NVIDIA GB10 / DGX Spark only, Linux `aarch64`, CUDA `sm_121a`.
- Model target is `Qwen/Qwen3.8-Flash-Next` only; immutable architecture mismatches fail closed.
- Native CUDA code must not compile unless the operator explicitly enables `native-cuda`.
- No CPU/mock/stub backend may satisfy a CUDA test or native capability gate.
- `compute_121a` / `sm_121a` artifacts are architecture-specific; M2 does not add compatibility for other GPUs.
- Host-independent CI and GB10 native evidence are separate proof classes.
- No performance claim is permitted in M2 until an end-to-end benchmark exists; M2 kernel measurements are correctness/smoke evidence only.
- Every production behavior change follows RED -> verify RED -> minimal GREEN -> full gate.
- Checkpoint/source identity must be recorded and checked before binding model files.

- Modify: `crates/gb10x-cuda/src/lib.rs`

**Interfaces:**
- Feature: `native-cuda`.
- C ABI struct `gb10x_cuda_device_info_v1` containing ABI version, device ordinal, CC major/minor, total memory, L2 bytes, persisting-L2 max bytes, SM count, warp size, and fixed UTF-8 device name buffer.
- C ABI function `int gb10x_cuda_probe_device(int ordinal, gb10x_cuda_device_info_v1* out)`.
- Rust `CudaDeviceInfo` and `probe_device(ordinal: i32) -> Result<CudaDeviceInfo, CudaNativeError>` available only with `native-cuda`.

- [ ] **Step 1: Add RED ABI/layout tests**

Host-independent tests assert Rust-side validation rejects:
- ABI version != 1;
- CC != 12.1;
- zero L2/total memory/SM count/warp size;
- invalid/non-terminated device name.

Native test, compiled only with `native-cuda`, calls `probe_device(0)` and asserts discovered fields are nonzero; it does **not** hard-code published cache capacities.

- [ ] **Step 2: Verify host RED**

Run: `cargo test -p gb10x-cuda --all-targets`

Expected: FAIL because ABI conversion/validation is missing.

- [ ] **Step 3: Implement native build path**

`build.rs` must:
- do nothing native when `CARGO_FEATURE_NATIVE_CUDA` is absent;
- require `nvcc` when present;
- compile `probe.cu` with `--generate-code=arch=compute_121a,code=sm_121a`;
- compile PIC object and archive it into `libgb10x_cuda_native.a`;
- link CUDA Runtime (`cudart`) and C++ runtime as required;
- fail with a clear message if `nvcc` cannot compile `sm_121a`.

- [ ] **Step 4: Implement probe.cu**

Use CUDA Runtime API only inside C++ to query device identity/properties. Copy values into the stable C ABI struct. CUDA errors return a negative/explicit status and never synthesize values.

- [ ] **Step 5: Verify host GREEN**

Run host workspace gates without `native-cuda`; expected PASS and no CUDA dependency.

- [ ] **Step 6: Verify native compile on DGX Spark**

Run on Spark:

```bash

nvcc --version
cargo test -p gb10x-cuda --features native-cuda --all-targets
```

Expected: `aarch64`; CUDA test binary compiles and executes; probe reports CC 12.1.

## Plan self-review

- M2 stays bounded to the native execution foundation; it does not attempt GDN, QSA, MoE, MTP, CUDA Graph supergraphs, L2 persistence policy, ARM SVE2 kernels, L3Draft, ExpertScout or serving.
- No CUDA runtime claim can be produced by host CI.
- No generic GPU/model abstraction is introduced.
- The safetensors task closes the explicit M1 gap between prepared flat PLE rows and the real model files.
- The first model-math kernel is intentionally RMSNorm because its oracle is small, deterministic and isolates CUDA ABI/memory/reduction correctness before attention/MoE complexity.
- All native paths are real CUDA or absent; no fake backend exists.
